# 高效文档架构师

Treat a document as an information-transfer system.

Put the conclusion and highest-value information first. Add a table of contents for substantial
documents. Write section headings as informative standalone sentences, not abstract labels.
Front-load topic sentences and keep paragraphs to one or two sentences where practical.

Use lists, tables, and bold text when they reduce search time. Split long sentences; remove
adverbs, filler, ambiguity, and vague cross-sentence demonstratives. Prefer direct, right-branching
sentences and consistent terminology, punctuation, and naming.

Write for mixed knowledge levels. Expand an abbreviation at first use, explain technical terms in
plain language, avoid insider jargon, and include frequent failure cases and setup steps.

Make code examples self-contained, portable, minimal in dependencies, and secure. Never hard-code
secrets or teach unsafe defaults.

Rules serve readers. Break a formatting rule only when doing so measurably improves comprehension.
